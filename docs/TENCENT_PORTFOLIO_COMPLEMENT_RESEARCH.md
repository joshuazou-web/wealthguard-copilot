# 腾讯自选股微信版 / 微证券：补充型产品研究

> 调研日期：2026-09-04。本文区分“公开资料可验证事实”“用户截图观察”和“产品推断”。WealthGuard 是独立求职作品，未接入腾讯接口，也不代表腾讯或合作券商。

## 结论先行

WealthGuard 不应成为另一个行情终端、财经资讯流、AI 问股助手、智能盯盘工具或交易入口。腾讯自选股已经在这些环节拥有微信/QQ 入口、沪深港美行情、内容与社区、提醒、ETF 工具、合作券商连接，以及持续增强的 AI 能力。正面复制既没有渠道优势，也会弱化案例的产品判断。

更合理的角色是 **Evidence & Quality Guard（证据与质量增强层）**：

1. 在腾讯自选股、元宝或 StockBuddy 形成答案后，对关键结论执行资料版本、证券代码、页码引用和确定性计算核验；
2. 当证据不足、资料冲突、模型失败或越过投顾/交易边界时，返回可解释的 caution / abstain / refuse 信号；
3. 把线上坏答案转成可筛选、可归因、可关联回归测试的质量运营案例；
4. 核验结束后回到原有自选、资讯或券商链路，不争夺行情、账户与交易主流程。

## 用户旅程与增强插槽

```text
微信/QQ入口 → 自选与行情 → 资讯/AI解释 → 用户形成判断 → 券商承接交易
                             │
                             ├─ 深度核验：证券代码 + 文件版本 + 页码原文
                             ├─ 确定性工具：比率、费用、波动、回撤
                             ├─ 安全门：证据不足/冲突/越界时停止
                             └─ 质量闭环：坏案例 → 责任层 → 修复 → 回归
                                      （WealthGuard）
```

### 三个互补场景

1. **财报深证据模式**：用户在个股小报或 AI 搜索看到原因解释后，点“核验原文”，进入按事实 / 计算 / 系统解释分层的页码级证据视图。
2. **公告时效模式**：用户从资讯或自选提醒进入公告，系统先核对证券代码、生效日期、版本替代和冲突，再允许生成摘要。
3. **证券比较护栏**：主产品继续提供行情与产品发现；WealthGuard 只识别最可能改变路径的缺失条件，计算可比指标，不制造“唯一最佳”。

### 双向集成契约（产品设想，未实现外部连接）

建议输入字段：`source_surface`、`security_id`、`market`、`document_id`、`document_version`、`as_of`、`user_question`、`candidate_answer`、`claim_ids`。禁止输入账户密码、身份证件、真实持仓或交易指令。

建议输出字段：`decision`（pass/caution/abstain/refuse）、`verified_claims`、`removed_claims`、`source_locators`、`calculation_trace`、`freshness_status`、`quality_tags`、`audit_id`。返回后由腾讯自选股或 StockBuddy 决定如何展示；WealthGuard 不路由交易。

## 为什么这个切口能长期成立

- 行情、资讯和通用问答越强，错误的影响面越大，质量治理的边际价值越高。
- 证据校验、版本治理和回归运营是跨模型能力，不依赖某个模型“更聪明”。
- 它与腾讯金融科技公开强调的连接金融机构、合规与风险管理方向一致，但本文不据此声称获得内部认可。
- 对产品团队而言，坏案例后台能把“AI 偶尔会错”变成可分母化、可分责、可排期的迭代对象。

## 尚未验证的假设

- 腾讯自选股真实用户中，点击原文、对比版本和查看计算轨迹的需求规模；
- 现有 AI 答案的真实错误分布、线上延迟预算与内部评测基础设施；
- 腾讯自选股、元宝、StockBuddy 是否提供可用的结构化上下文接口；
- 质量信号应在回答前同步阻断，还是回答后异步抽检；
- 券商、交易所资料授权和内部合规对缓存、展示及日志保留的要求。

这些假设需要腾讯内部访谈、5–8 名目标用户测试和受控灰度验证，不能从公开资料推断。
